> 기준: `AI 활용 아이디어 기획서` **2안 시트** (선임계리사지원 / 이우현)

### PoC 범위를 이렇게 좁히세요 (1일 기준)

```
[검색창] 키워드 + 판매기간(From~To) + 상품분류 필터
     ↓
[결과 목록] 상품명 | 분류 | 판매기간 | 판매상태 | 개정차수
     ↓ 클릭
[상품 상세 카드] 기본정보 + 담보 목록(감액/면책) + 최근 포트폴리오 + 관련 문서 요약
     ↓
[AI 요약] "이 상품 핵심 3줄 요약" (선택: Claude API / 미연동 시 규칙 기반 요약)
```

- **하지 않을 것**: 실제 PDF 파싱, 로그인/권한, 사내 시스템 연동, 대용량 벡터DB
- 권장 기술: **단일 HTML + JavaScript(CSV 로드)** 또는 **Python Streamlit** 중 하나 (Claude Code에 "가장 단순하게"라고 지시)

## 2. 핵심 업무 규칙 (Logic) · 조건 · 계산식

Claude Code에 **그대로 붙여넣을 수 있도록** 규칙 형태로 정리했습니다.

### R1. 판매상태 판정
```
기준일 D (기본값: 오늘)
판매중   : sale_start <= D AND (sale_end IS NULL OR sale_end >= D)
판매종료 : sale_end < D
판매예정 : sale_start > D
```

### R2. 판매시기 검색 (기간 겹침) — 가장 중요
사용자가 조회기간 [From, To]를 입력하면, **그 기간에 하루라도 판매된 상품**을 찾는다.
```
sale_start <= To  AND  (sale_end IS NULL OR sale_end >= From)
```
- 예) 2020-01-01 ~ 2020-12-31 조회 → P002, P004, P006, P008, P009, P012 (+P001/P010 제외 확인)
- 특정 시점 조회(From = To)도 같은 식으로 처리

### R3. 키워드 검색
```
1) 입력값 공백 제거·소문자화 (예: "든든 종신" → "든든종신")
2) 검색 대상 필드: product_name, key_features, coverage_name, payment_reason, documents.title, documents.content
3) 동의어 사전이 있으면 키워드를 확장 (암 → 암, 악성신생물, 유사암)
4) 다중 키워드는 AND 조건 (예: "종신 저해지")
5) 담보/문서에서 걸린 경우 → 해당 product_code로 묶어서 상품 단위로 결과 표시
```

### R4. 검색결과 정렬
```
1순위: 일치 점수 (상품명 일치 3점, 담보명 2점, 문서/특징 1점 합산)
2순위: sale_start 최신순
```

### R5. 개정 이력(상품군) 묶음
```
같은 product_group 내 상품을 revision_no 오름차순으로 나열 → "개정 이력 타임라인" 표시
최신판 = 같은 product_group 중 revision_no 최댓값
변경점 = 직전 차수 대비 assumed_rate, refund_type, renewable, 담보 추가/삭제 비교
```

### R6. 포트폴리오 지표
```
최신 기준월     = MAX(base_month)
상품 비중(%)    = 해당상품 reserve_100m / 전체 상품 reserve_100m 합계 × 100   (기준월 동일)
전월 대비 증감률 = (당월 policy_count − 전월 policy_count) / 전월 policy_count × 100
```

### R7. 감액·면책 반영 지급액 (상세 카드 예시 계산기)
```
경과일 t, 가입금액 S
if t < waiting_days                     → 지급액 = 0 (면책)
elif t < reduction_months × 30.4(일)    → 지급액 = S × payment_pct% × reduction_pct%
else                                    → 지급액 = S × payment_pct%
```
- 예) P007 일반암진단, S=3,000만원, 경과 200일 → 3,000 × 100% × 50% = **1,500만원**

### R8. AI 요약 규칙 (환각 방지)
```
- 요약은 반드시 "검색된 레코드(상품·담보·문서)만" 근거로 작성
- 각 문장 끝에 근거 문서ID 표기 (예: [D003])
- 데이터에 없는 내용은 "자료 없음"으로 표시, 추정 금지
- 형식: ①상품개요 1줄 ②주요 담보·감액/면책 1줄 ③개정 포인트·특이사항 1줄
```

## 5. 실제 내부 자료를 대체할 더미데이터 생성 가이드

### 5-1. 반드시 지킬 원칙
1. **가상 회사명** 사용: "가나다생명" (실제 회사명·상품명·상품코드 사용 금지)
2. 예정이율, 지급비율, 감액·면책 기간은 **업계 일반 수준의 그럴듯한 값**으로만 (자사 실제값 복사 금지)
3. 포트폴리오 수치(건수·준비금)는 **난수로 생성** — 자사 실적 규모를 추정할 수 없게
4. 문서 content는 **직접 새로 작성한 요약문** (실제 상품위원회 문구 붙여넣기 금지)
5. 개인정보(계약자·피보험자) 컬럼은 **아예 만들지 않음** — 이 과제에는 필요 없음

### 5-2. 꼭 포함해야 할 "검증용 케이스" (더미데이터 설계 포인트)
- [x] 판매중(sale_end 빈값) 상품과 판매종료 상품 혼합
- [x] **같은 상품군의 1·2·3차 개정** (G01 종신, G02 건강, G03 암) → 개정 이력 기능 검증
- [x] 같은 담보명이 여러 상품에 존재 (3대질병진단, 사망보험금, 유사암진단) → 담보명 검색 검증
- [x] 감액/면책이 있는 담보와 없는 담보 혼합
- [x] 갱신형/비갱신형, 표준형/저해지형/무해지형 혼합
- [x] 판매종료된 상품에도 포트폴리오(보유계약)가 남아있음 (감소 추세)

### 5-3. 더 늘리고 싶을 때 Claude Code에 줄 프롬프트 (복사해서 사용)
```
dummy-data 폴더의 products.csv, coverages.csv, documents.csv, portfolio.csv 형식을 그대로 유지하면서
가상 회사 "가나다생명"의 상품을 30개로 늘려줘.
- 실제 존재하는 보험사명/상품명은 쓰지 마
- 판매개시일은 2015~2026년 사이, 판매종료일 빈값(판매중) 비율 40%
- 상품군별로 1~3차 개정이 있게 하고, 개정마다 예정이율·해지환급금유형·담보 중 1가지 이상 변경
- 상품당 담보 2~5개, 감액/면책 있는 담보 비율 50%
- 각 상품마다 상품위원회 문서 1개(200~400자 요약문)
- portfolio는 2025-07~2026-06 12개월, 판매중 상품은 증가, 판매종료 상품은 감소 추세
- 생성 후 product_code FK 무결성 검사 스크립트도 실행해줘
```

## 8. 기초서류 PDF 폴더 연결 (구현됨)

웹앱 상단 **[폴더 선택]** 버튼으로 PC의 기초서류 폴더(예: `C:\Users\...\상품기초서류폴더`)를 고르면,
브라우저가 PC 안에서 PDF 본문을 읽어 **같은 검색창(키워드·판매기간·분류·판매상태)** 으로 함께 검색합니다.

- **업로드 없음**: 파일은 메모리에서만 처리하고 어디에도 저장·전송하지 않습니다. 창을 닫으면 사라집니다.
- **인터넷 불필요**: PDF 엔진(pdf.js 3.11.174)과 한글 CMap을 `lib/`에 내장했습니다.
- **판매일자 인식**: 하위 폴더명(없으면 파일명)의 날짜를 판매개시일로 봅니다.
  `2023.01.01`, `2023-01-01`, `2023년 1월 1일`, `20230101`, `230101`, `2023.01`, `202301` 형식 지원.
  폴더명에 날짜가 2개면 시작~종료로 사용합니다.
- **판매종료일 추정**: 같은 상품명(파일명에서 날짜·문서유형 제외)의 다음 판매일자 하루 전을 종료일로 표시합니다 `(추정)`.
  마지막 판매일자 폴더의 상품은 종료일을 알 수 없어 "판매중"으로 간주됩니다.
- **문서유형**: 파일명에 `사업방법서 / 산출방법서 / 상품요약서 / 약관`이 들어 있으면 자동 분류합니다.
- **결과**: 일치한 문장(페이지 번호 포함)을 보여주고, [열기]를 누르면 해당 페이지로 PDF가 열립니다.
- **스캔 이미지 PDF**는 글자 정보가 없어 본문 검색이 안 됩니다(경고 표시).
- 실습용 가상 샘플: `sample-기초서류폴더/` (판매일자별 하위폴더 구조)
- `.gitignore`가 샘플 외의 모든 PDF를 커밋 대상에서 제외합니다 → 실제 문서를 이 폴더에 넣어도 GitHub에 올라가지 않습니다.

## 9. 질문 검색 · 상품 분석 (오프라인, 구현됨)

### 질문 검색
검색창에 문장으로 물어보면 **특징 사전**(`dummy-data/features.csv`)과 대조해 상품을 찾습니다.

- 예) `제1보기와 제2보기가 구분되어있는 종신보험이 뭐였지?` → 특징 **보기 구분형** + 분류 **종신**
- 검색창 아래 **질문 해석** 칩으로 어떻게 이해했는지 보여주고, `×`로 해석을 뺄 수 있습니다.
- 판매상태(`판매중`, `판매종료`), 연도(`2023년`), 분류(`종신`, `건강` …)도 문장에서 인식합니다.
- 특징이 하나도 인식되지 않으면 기존 키워드 검색으로 동작합니다(기존 테스트 4개 그대로 통과).
- 결과는 **상품별 카드**: 근거 문서·페이지 문장, [상품 분석 보기], [PDF 열기].

**특징 추가 방법** — `dummy-data/features.csv`에 한 줄 추가 후 `python build-data.py` (또는 `start.bat`) 실행

| 컬럼 | 의미 | 예 |
|---|---|---|
| feature_name | 화면 표시명 | 보기 구분형 |
| question_phrases | 질문에 나올 표현(; 구분, 공백 무시) | 보기구분;제1보기;제2보기 |
| doc_patterns | 문서에서 찾을 패턴(; 구분, **모두** 있어야 일치, 정규식, 공백 무시) | 제1보기;제2보기 |

### 상품 분석 (사업방법서·상품요약서·약관 → 핵심 특징 표)
결과 카드의 **[상품 분석 보기]** 또는 PDF 결과의 **[분석]** 버튼. 판매일자별로 바꿔 볼 수 있습니다.

- 출력 형식: 한눈에 보기 / 핵심 특징 표(보험종류~기타 11개 항목 + 문서 근거) / 유의사항 / 확인 필요 항목
- **원문 줄을 그대로 인용**합니다(요약·환산·추측 없음). 근거 `(사업방법서 p.2)`를 누르면 해당 페이지가 열립니다.
- 못 찾은 항목은 **"문서 내 확인 불가"**, 세 문서 중 2개 이상에 나온 보험기간·납입기간·가입나이의 숫자가 서로 다르면 **[확인 필요]**.
- 같은 판매일자의 **사업방법서·상품요약서·약관을 모두** 찾아 문서별로 근거를 붙입니다(문서당 항목별 최대 3줄, 나머지는 "외 N줄"). 해당 판매일자 폴더에 없는 문서는 확인 필요 항목에 안내합니다.
- **[결과 복사]**: 마크다운 표로 복사(보고서·메일용)
- **[AI용 프롬프트 복사]**: 분석 프롬프트 + 문서 본문(페이지 표시 포함)을 클립보드로 복사 — 사내 승인된 AI에 직접 붙여넣는 용도. 앱은 아무것도 전송하지 않습니다.
- 한계: 규칙(키워드) 기반이라 항목 분류가 틀릴 수 있고, 표가 복잡한 PDF는 줄이 섞일 수 있습니다. 반드시 근거 페이지로 원문 확인.

실습용 가상 샘플: `sample-기초서류폴더/2024.03.01`, `2025.06.01`의 `(무)가나다두갈래종신보험` (2024판만 제1·제2보기 구분, 가입나이 문서 간 불일치 포함)

## 10. 내 폴더 자동 연결 (start.bat · serve.py)

창을 닫을 때마다 폴더를 다시 고르지 않도록, **파이썬 로컬 실행기**로 지정 폴더를 자동 연결합니다. 추가 설치(pip) 없음.

1. `poc-2an\start.bat` 더블클릭
2. **처음 한 번만** 검은 창에 기초서류 폴더 경로를 붙여넣고 Enter
   (예: `C:\Users\user\Desktop\App_261014\doc_sample_2026\2026`) → `docs-folder.txt`에 저장
3. 브라우저가 `http://127.0.0.1:8765` 로 열리고 폴더를 자동으로 읽습니다.
4. 다음부터는 `start.bat`만 실행 → 바로 검색 (검은 창을 닫으면 앱 종료)

- **검색 색인**: PDF에서 읽은 글자를 `poc-2an\.docs-cache\index.db`(SQLite)에 저장 → 다음 실행부터는 **새로 추가·수정된 파일만** 다시 읽고, 삭제된 파일은 색인에서 자동으로 뺍니다.
  초기화하려면 `.docs-cache` 폴더 삭제. (자세한 내용은 11장)
- **폴더 추가·변경 반영**: 실행 중 PDF를 넣었다면 앱의 [새로고침] 버튼. 다른 폴더로 바꾸려면 `python serve.py --folder "C:\새\폴더"`
- **보안**: 이 PC(127.0.0.1)에서만 접속되고 외부로 전송하지 않습니다. 지정 폴더 밖의 파일은 열 수 없습니다.
  `.docs-cache`와 `docs-folder.txt`는 `.gitignore`로 GitHub에 올라가지 않습니다.
- `index.html`을 더블클릭해서 여는 기존 방식([폴더 선택])도 그대로 동작합니다.

## 11. 대량 문서 대응 — 검색 색인 (1단계)

전체 기초서류(수천 개 PDF)를 넣어도 느려지지 않도록, `start.bat`으로 실행하면 **검색이 내 PC의 SQLite 색인에서** 이뤄집니다.
브라우저에는 문서 목록과 화면에 보이는 결과만 올라옵니다. (파이썬 기본 기능만 사용, 추가 설치 없음)

| 구분 | 방식 |
|---|---|
| 글자 추출 | 처음 한 번 브라우저(pdf.js)가 읽어 색인에 저장. 이후엔 새로 추가·수정된 파일만. **중간에 창을 닫아도 다음 실행 때 이어서** 진행 |
| 키워드 검색 | 공백을 뺀 본문을 3글자 단위로 색인 → 부분 일치 검색 (예: "제 1 보기"도 `제1보기`로 찾음) |
| 질문(특징) 검색 | 색인할 때 특징 태그를 미리 계산 → 즉시 응답. `features.csv`를 고치면 다음 실행 때 저장된 글자로 자동 재계산(PDF 다시 안 읽음) |
| 상품 분석 | 해당 상품·판매일자 문서의 본문만 그때 가져와 분석 |

**성능 시험 결과** (가상 문서 1,000개 × 40쪽 ≈ 3,700만 자, 이 개발 환경 기준)
- 색인 용량 약 185MB (문서 수에 비례 → 5,000개면 1GB 안팎 예상)
- 검색: 드문 단어 수 ms, 거의 모든 쪽에 나오는 단어 30~160ms, 어디에도 없는 1~2글자 단어 약 1초
- 특징 사전 변경 시 전체 재계산 약 7초
- 실제 PDF 첫 색인은 브라우저 추출 속도에 좌우됩니다(파일당 0.3~1초 예상 → 수천 개면 수십 분). 진행률과 남은 시간이 화면에 표시되고, 색인된 문서부터 바로 검색됩니다.

**참고**
- 브라우저: **크롬으로 엽니다** (설치 경로·레지스트리에서 찾고, 없으면 Windows 기본 브라우저). 기본 브라우저로 열려면 `python serve.py --browser default`
- 폴더 바꾸기: `change-folder.bat` 실행 후 경로 붙여넣기 (또는 `python serve.py --folder "경로"`). **폴더별 색인은 따로 보관**되므로 예전 폴더로 돌아가도 다시 읽지 않습니다.
- 자동 연결 폴더는 앱 폴더의 `docs-folder.txt`에 저장됩니다. 저장소를 다른 위치에 새로 내려받으면 이 파일과 색인(`.docs-cache`)이 없으므로 처음에 경로를 다시 묻고 새로 읽습니다.
- 이전 버전의 캐시(`.docs-cache\*.json`)는 첫 실행 때 자동으로 색인으로 옮겨집니다.
- 더블클릭(`index.html`) 방식은 예전처럼 메모리에서 동작합니다(소량 문서·교육 시연용).

## 12. 상품 비교 · 개정 전후 비교 (2단계)

### 비교함에 담기
- 상품 분석 화면의 **[비교에 추가]**, 또는 질문 답변 카드의 **[비교 담기]** → 화면 아래 **비교함**에 담김 (상품·판매일자 단위, 최대 4개)
- 2개 이상 담으면 **[비교하기]**

### 상품 비교
- 11개 항목(보험종류~기타)을 상품별로 나란히 — 내용은 원문 줄 그대로, 근거 페이지 링크 포함
- 항목별 자동 판정: **같음 / 숫자 다름 / 표현 다름 / 구분 다름 / 일부 확인 불가** (다른 행은 노란색)
- **[다른 항목만]** 체크로 차이 나는 항목만 보기

### 개정 전후 비교 (같은 상품의 두 판매일자)
- 상품 분석 화면에서 **[이전 판매일자와 비교]** 한 번에 실행 (또는 같은 상품 2개를 비교함에 담기)
- 위 비교표 + **문서별 바뀐 줄**(사업방법서·상품요약서·약관):
  - **변경**: 항목명이 같은 줄의 내용이 바뀜 (예: `가입나이: 제1보기 15세~65세…` → `가입나이: 15세~65세`)
  - **삭제 / 추가**: 한쪽 판에만 있는 줄
  - 줄 앞 번호만 바뀐 경우는 같은 줄로 봄. 한쪽 판에 해당 문서가 없으면 "비교 불가"로 표시

### 내보내기
- **[마크다운 복사]**: 보고서·메일 붙여넣기용 표
- **[엑셀 저장(CSV)]**: 엑셀에서 바로 열리는 파일(한글 깨짐 없음). 개정 비교는 바뀐 줄 전체 포함

### 한계
- 줄 단위·규칙 기반 판정입니다. PDF에서 한 문장이 두 줄로 나뉘면 따로 비교될 수 있으니, 판정은 참고용으로 보고 근거 페이지에서 원문을 확인하세요.

## 13. 상품 목록 자동 구성 (3단계)

화면 메인(검색창 바로 아래)에 항상 보이는 **상품 목록** — 불러온 문서를 **상품별**로 묶어 한눈에 봅니다.

| 열 | 내용 |
|---|---|
| 상품명 · 분류 | 파일명에서 추출한 상품명, 상품명으로 판정한 분류(종신·건강·암 …) |
| 상태 | 최신 판매일자 기준 판매중/판매종료 (폴더 날짜로 추정) |
| 판매일자 | 판매일자(버전) 목록 — 누르면 해당 판매일자의 상품 분석 |
| 문서 | 사=사업방법서 · 요=상품요약서 · 약=약관 (진한 글자 = 있음) → 빠진 문서 점검용 |
| 특징 | 특징 사전의 12개 특징 — ● 최신 판매일자에 있음, ○ 과거 판매일자에만 있음 |

- **필터**: 상품명 검색, 분류, 상태, 특징(예: "보기 구분형"이 있는 상품만)
- **[판매일자별로 펼치기]**: 버전마다 한 줄 — 개정 때 특징이 언제 생기고 없어졌는지 확인
- 각 줄의 **[분석]**, **[비교 담기]** 로 바로 상품 분석·비교(2단계)로 연결
- **[엑셀 저장(CSV)]**: 판매일자(버전) 단위로 상품명·판매기간·상태·문서 구비(Y)·특징(Y)·파일 경로 (현재 필터 적용)
- 한계: 판매상태·종료일은 폴더 날짜로 추정합니다. **가장 최근 폴더에만 있는 상품은 실제로 판매가 끝났어도 "판매중"으로 보입니다.**
  상품명이 파일마다 다르게 적혀 있으면 다른 상품으로 나뉠 수 있습니다.
- 상품 묶기 규칙: 파일명에서 `[보험약관]` 같은 대괄호 머리표, 문서유형(보험약관·보통약관·사업방법서 …), 날짜, **`계약자용` 표기**를 빼고 공백을 무시해 비교합니다. `무배당 ○○`과 `(무)○○`도 같은 상품으로 봅니다.

## 14. 보험금 지급사유·감액·면책 — 약관 "보험금 지급기준표" 기준

상품 분석의 **보험금 지급사유 · 감액 · 면책** 3개 항목은 약관의 **보험금 지급기준표와 그 아래 주석**에서 뽑습니다.

| 항목 | 가져오는 곳 | 판정 기준 |
|---|---|---|
| 보험금 지급사유 | 첫 번째(주계약) 지급기준표의 행 | `급부명칭 \| 지급사유 \| 지급금액` 형태로 행 단위 표시. 특약 지급기준표는 제목만 안내 |
| 감액 | 모든 지급기준표의 주석(주1), ※ 등)과 표 안 문장 | **기간 + 비율** — 예: "계약일부터 1년 미만 … 50%를 지급" |
| 면책 | 〃 | **기간·보장개시일 + 지급하지 않음** — 예: "보장개시일 … 90일이 지난 날의 다음날", "1년 이내 … 지급하지 않습니다" |

- 지급기준표에 감액·면책 조건이 없으면 **"없음"** 으로 표시합니다 (확인 불가와 구분). 상품 비교에서는 "있음/없음 다름"으로 판정합니다.
- **보험금 지급사유는 약관의 지급기준표를 그림으로 잘라 보여줍니다** (표 + 주석, 예시 상자 앞까지, 최대 2쪽). 칸에는 작은 미리보기와 **[지급기준표 보기]** 버튼만 두고, 누르면 큰 창으로 열립니다(Esc·바깥 클릭으로 닫기, 창 안에서 '원문 열기').
- 상품·개정 비교 화면의 **[지급기준표 나란히 보기]** 로 비교 중인 상품들의 지급기준표를 한 창에 나란히 봅니다.
- 글자로 읽은 결과는 "글자로 보기"에 접어 둡니다(복사·비교·엑셀 저장용 — 칸이 합쳐진 표는 칸 구분이 정확하지 않을 수 있음).
- 주석은 "(주)" 아래 1. 2. ① 같은 번호마다 나눠 판정하고, **보험금 지급 맥락이 없는 문장(공시이율·적립액 등)은 감액·면책에서 제외**합니다. 근거에는 어느 표(예: 별표2 암진단특약)의 주석인지 표시합니다.
- 목차 줄(`제5조【…】 ……27`)은 결과에서 뺍니다.
- 약관에 지급기준표가 없으면 확인 필요 항목에 "본문 문장에서 찾았습니다(정확도 낮음)"로 안내하고, 기간+비율 / 기간+지급하지 않음 규칙으로만 찾습니다.

## 15. 사업방법서 목차 기준 항목 (핵심 특징 표에 추가)

핵심 특징 표 기존 항목 뒤에 사업방법서 목차 순서로 13개 항목을 붙였습니다.

| 목차 | id | 표시명 | 목차 제목 별칭 (공백 제거 후 매칭) |
|---|---|---|---|
| 1 | kind | 종목·세목 | `보험종목의(명칭\|구성)`, `종목및세목` |
| 3 | mandatory | 의무가입 | `의무(가입\|부가)` |
| 4 | dividend | 배당 | `(계약자)배당…` |
| 5 | premium | 보험료 | `보험료(및보험가입금액)에관한사항` (할인·선납 제목은 제외) |
| 6 | discount | 보험료 할인 | `할인` |
| 7 | bonus | 유지보너스 | `유지보너스` |
| 8 | prepay | 보험료 선납 | `선납` |
| 9 | revival | 해지계약 부활 | `부활`, `효력회복` |
| 10 | overdue_rate | 연체이율 | `연체이(율\|자)` |
| 12 | loan | 보험계약대출 | `보험계약대출`, `약관대출` |
| 13 | partial_refund | 해약환급금 일부지급 | `환급금(의)일부지급` |
| 14 | simple_uw | 간편심사형 | `간편(심사\|고지)`, `유병자` |
| 15 | savings_type | 적립형 계약 | `적립형` |

- 목차 2번(보험기간·납입기간·가입나이·납입주기)은 기존 **보험기간·납입기간·가입나이** 행에, 11번(계약자적립액 인출)은 기존 **중도인출** 행에 연결합니다. "보험기간:"처럼 항목명이 붙은 줄이 있으면 그 줄을 먼저 씁니다(기존 결과 유지).
- **구역 인식**: "번호. 제목" 형태의 짧은 줄(45자 이하)부터 다음 번호(+1~+3) 제목 전까지. 구역 안의 가. / (1) / ① / 수식 속 "2." 등에서는 끊지 않고, 목차 줄과 별첨(서식) 이후는 보지 않습니다.
- 내용은 원문 줄 순서 그대로 8줄까지, 나머지는 "외 N줄 더 있음". 본문이 "해당사항 없음"이면 **"없음 (사업방법서 해당사항 없음)"**.
- 표가 있는 구역(짧은 줄이 많은 구역: 종목·세목, 2번 표, 보험료, 유지보너스, 적립형 등)은 **구역을 그림으로 잘라 미리보기 + [표 보기]** 로 보여줍니다(최대 3쪽).
- 제목을 못 찾으면 기존처럼 정규식으로 줄 단위 매칭, 그래도 없으면 "문서 내 확인 불가".
- 마크다운·엑셀 내보내기, AI용 프롬프트(추출 항목 12~24 추가), 상품·개정 비교에 모두 포함됩니다. 문서 간 숫자 대조([확인 필요])는 "유지보너스:"처럼 항목명이 붙은 줄끼리만 합니다.
